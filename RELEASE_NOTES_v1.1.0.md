## 这个版本新增什么

接入[水鱼查分器](https://diving-fish.com)。这部分**与 qq-bridge 无关**，桥接没装好也能用。

**QQ 命令（任何人可用，不限管理员）**

```
#查分                     我的查分状态（OAuth 是否配好、画图库是否可用、曲库缓存）
#查分 b50 某人             公开查询某人的 B50，并出一张成绩图
#查分 某人                 同上（子操作可省）
#查分 search ztn          搜曲，支持简写（→ Zitronectar）
#查分 song 11823          查某首歌的全部难度定数

#查分 bind                绑定水鱼（授权链接私发给本人，群里看不到）
#查分 confirm <确认码>     用页面给出的一次性确认码收尾绑定
#查分 b50                 绑定后这条就查你自己的成绩
```

**DSH 工具面**：`qqbridge` 新增第 10 个 action `maimai`，子操作同上。

**成绩图**：1080 宽 PNG，按内容自适应高度。桥接会**自动把它发到 QQ**（另起一条消息），
并且在转发前把文本里的**本机文件路径剥掉**——聊天记录里不会出现你电脑的目录结构。

## 权限与安全（这部分值得单独读）

### 为什么查分不要求管理员

`#余额` / `#关机` / `#功能` 操作的是**机器人自身**（钱、进程、工具面），所以有 admin 门。
`#查分` 不是——它的权限模型是**逐用户 OAuth**：每个人用自己的水鱼账号授权，机器人只在
他本人点过「同意」后才读得到他的成绩，随时可撤销。所以"谁能查"由水鱼那边的授权决定，
桥接再设一道 admin 门没有增加安全性，只会让这功能对群里其他人等于不存在。

### 刻意不支持"按 QQ 号随便查"

水鱼已弃用开发者 token（`DIVINGFISH_TOKEN`），原因是它**能按 QQ 号读取任意用户的成绩**，
而那些用户从未授权、也无法撤销。用它做出来的"查分"本质是无需同意即可窥探他人成绩的工具。
所以本插件**只实现 OAuth**：

| 环节 | 做法 |
| --- | --- |
| 机器人持有的凭据 | 只有你自己申请的应用 `clientId` / `clientSecret` |
| QQ 号 | 只以 `sha256("<clientId>:<QQ号>")` 摘要外发，**号码本身不离开机器人** |
| 用户令牌 | 只在**内存**缓存（5 分钟，提前 30 秒失效），**不落盘** |
| 绑定 | 本人点「同意授权」→ 把页面给的**一次性确认码**发回来 |
| 撤销 | 随时可在 https://auth.diving-fish.com/apps 撤销 |

那个确认码不是多余手续：绑定链接谁都能转发，而确认码只出现在**点同意那个人的浏览器**里，
所以它验的是"点同意的人"和"发起绑定的人"是不是同一个。

### 绑定链接**只走私聊**

授权链接的语义是"为你自己的账号授权"。若发到群里，任何人点开、看到页面上的绑定身份、
点同意，就把**他自己的**账号绑到了发起者名下——正是确认码机制要防的转发攻击，
只不过这次是机器人自己把链接放进了群里。

所以 `bind` / `confirm` 无论从哪发起都**只发私聊**，群里最多一句"已私发给你，请到私聊查看"
（不含链接、不含确认码）。私聊失败（例如机器人还不是你好友）**绝不退回群发**，而是明确报错。

## 安装

```bat
git clone https://github.com/xueyingneko/qqbridge-plus.git "%USERPROFILE%\dsh-plugins\qqbridge-plus"
node "%USERPROFILE%\dsh-plugins\qqbridge-plus\scripts\install.mjs" --dir "%USERPROFILE%\dsh-plugins\qqbridge-plus"
```

安装器现在会**自动装好成绩图依赖**，并在装完后**实测渲染一张 PNG** 才报成功——
不只看"命令返回 0"（N-API 预编译包在少数平台可能装到却加载失败，那种失败暴露得太晚）。
万一没装上，插件其余部分照常可用，`#查分` 会明确告诉你去装什么。

**要查自己的成绩**，还需在 https://auth.diving-fish.com/apps 申请 OAuth 应用，把
`clientId` / `clientSecret` 写进 profile 的 `cordis.patch.yml`：

```yaml
    maimai:
      clientId: '你的应用 ID'
      clientSecret: '你的应用密钥'
      proxy: false
```

申请时：**接入方式选「bot / 工具」**，部署形态选「由你自己部署运行」，
权限**只勾三项只读**（`profile`、`prober.profile.read`、`prober.records.read`）。
不要勾任何 `write`——插件没有写入路径，而且含 write 的申请会被转人工审核。

# v1.1.0 — English

Adds **maimai DX score lookup**: query scores and render score images from QQ. Everything else
is unchanged.

> This code was generated by AI. Many thanks to
> [Derpyu520](https://github.com/Derpyu520) for building
> [qq-bridge](https://github.com/Derpyu520/qq-bridge) — without it this plugin would have no
> reason to exist. The score-lookup part follows the API contract and OAuth design of
> [Yuri-YuzuChaN/maimaiDX](https://github.com/Yuri-YuzuChaN/maimaiDX) (MIT).

## What's new

Integrates the [Diving-Fish](https://diving-fish.com) score service. This part is **independent
of qq-bridge** and works even if the bridge is not installed.

**QQ commands (usable by anyone, not just the admin)**

```
#查分                     my lookup status (OAuth configured? canvas available? music cache?)
#查分 b50 <name>          public B50 lookup for someone, renders a score image
#查分 <name>              same (the subcommand can be omitted)
#查分 search ztn          song search, abbreviations work (→ Zitronectar)
#查分 song 11823          all difficulty constants for one song

#查分 bind                start binding (the auth link is sent privately; the group never sees it)
#查分 confirm <code>      finish binding with the one-time code from the page
#查分 b50                 after binding, this looks up your own scores
```

**DSH tool surface**: `qqbridge` gains a 10th action, `maimai`, with the same subcommands.

**Score images**: 1080px wide PNG, height adapts to content. The bridge **sends it to QQ
automatically** (as a separate message) and **strips the local file path** from the text before
forwarding — your machine's directory layout never appears in the chat log.

## Permissions and safety

### Why score lookup does not require admin

`#余额` / `#关机` / `#功能` act on the **bot itself** (money, process, tool surface), so they
are gated. `#查分` is not: its permission model is **per-user OAuth** — each person authorizes
with their own Diving-Fish account, and the bot can only read a user's scores after that user
explicitly consented, revocable at any time. Who may query is therefore decided by Diving-Fish,
not by a second admin gate; adding one would only make the feature invisible to everyone else.

### It deliberately does not support "look up anyone by QQ number"

Diving-Fish has deprecated its developer token (`DIVINGFISH_TOKEN`) precisely because it could
**read any user's scores by QQ number**, without those users ever consenting or being able to
revoke. A "lookup" built on it is a tool for reading others' scores without consent. So this
plugin implements **OAuth only**:

| Aspect | Approach |
| --- | --- |
| Credentials the bot holds | Only your own application's `clientId` / `clientSecret` |
| QQ number | Sent only as `sha256("<clientId>:<QQ>")` — **the number itself never leaves the bot** |
| User tokens | In-memory only (5 min, 30 s safety margin), **never written to disk** |
| Binding | The user clicks "authorize", then sends back the **one-time confirmation code** |
| Revocation | Anytime at https://auth.diving-fish.com/apps |

That confirmation code is not a formality: a binding link can be forwarded by anyone, while the
code only appears in **the browser of the person who clicked authorize** — so it verifies that
the person who consented is the person who initiated the binding.

### Binding links are **private-message only**

An auth link means "authorize *your* account". If it were sent to a group, anyone there could
open it, see the binding identity shown on the page, and consent — binding **their own** account
to whoever started the command. That is exactly the forward-the-link attack the confirmation code
exists to prevent, except the bot would have put the link in the group itself.

So `bind` / `confirm` are **always sent privately** regardless of where they are issued; the group
sees at most "sent to your private chat" (no link, no code). If the private send fails (e.g. the
bot is not yet your friend), it **never falls back to the group** — it reports the failure.

## Install

```bat
git clone https://github.com/xueyingneko/qqbridge-plus.git "%USERPROFILE%\dsh-plugins\qqbridge-plus"
node "%USERPROFILE%\dsh-plugins\qqbridge-plus\scripts\install.mjs" --dir "%USERPROFILE%\dsh-plugins\qqbridge-plus"
```

The installer now **installs the score-image dependency automatically** and then **renders a test
PNG** before reporting success — not just "the command exited 0" (a prebuilt N-API package can
install yet fail to load on some platforms, and that failure surfaces far too late). If it does
not install, everything else still works and `#查分` tells you exactly what to install.

**To look up your own scores**, register an OAuth application at
https://auth.diving-fish.com/apps and put `clientId` / `clientSecret` into the profile's
`cordis.patch.yml`:

```yaml
    maimai:
      clientId: 'your app id'
      clientSecret: 'your app secret'
      proxy: false
```

When registering: choose **"bot / tool"** as the integration type, **"self-hosted"** as the
deployment form, and check **only the three read scopes** (`profile`, `prober.profile.read`,
`prober.records.read`). Do not request any `write` scope — the plugin has no write path, and
applications including write are routed to manual review.

- Added `dependencies: @napi-rs/canvas` (for score images; N-API prebuilt, **no** toolchain needed).

## Known limitations

- **Score images have no song jackets.** The upstream project's artwork is SEGA game material and
  cannot be bundled into an MIT repository, so cards use a stable colour strip derived from the
  song title instead.
- **Unbound users can only use public lookup** (by username, requires the target to have made their
  scores public). Looking up your own scores requires binding first.
- Several changes live in qq-bridge locally (image delivery, command entry, forced private
  messaging) and are **not part of the official qq-bridge release**. When upgrading qq-bridge,
  re-apply them from the two patch documents under `docs/` in this repository. One of them —
  constructing `cfg.maimaiCommand` explicitly — **fails completely silently** if missed (commands
  do nothing, and the log shows no clue).
